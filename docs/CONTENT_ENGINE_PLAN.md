# 콘텐츠 엔진 MVP 기획서

작성일: 2026-06-26

## 목표

`bartkoh-blog`의 콘텐츠 엔진은 비개발자가 Claude, Codex, 바이브코딩을 두려워하지 않도록 돕는 블로그 초안을 만든다.

핵심은 일반적인 AI 도구 소개가 아니다. 대표님의 실제 개발 기록, Obsidian 메모, 시행착오를 바탕으로 초심자가 막히는 지점을 아주 친절하게 풀어주는 글을 만든다.

## 목표 독자

- ChatGPT는 써봤지만 Claude Code, Codex, GitHub, Vercel, Supabase는 막막한 사람
- 전문 개발자 유튜브를 보면 너무 빨라서 따라가기 힘든 사람
- 코딩을 배우기보다 AI와 함께 웹 제품을 만들고 싶은 비개발자, 대표, 기획자, 1인 사업자

## 입력 자료

1차 MVP는 사용자가 명시한 폴더만 읽는다.

예:

```powershell
corepack yarn content:draft -- --source E:\dev\obsidian-vault\허용폴더 --topic "비개발자를 위한 Codex 시작법"
```

원천 자료 후보:

- Codex 작업 기록 MD
- Claude/Claude Code 사용 기록 MD
- Obsidian의 AI, 자동화, 제품 개발, 바이브코딩 관련 노트
- `bartkoh-blog` 안의 기존 블로그 글

## 민감정보 제외 규칙

엔진은 원본 파일을 수정하지 않는다. 다만 초안과 보고서를 만들 때 아래 정보는 경고하거나 가린다.

- 이메일, 전화번호, API 키, 토큰, 비밀번호처럼 계정과 보안에 관련된 값
- 사람 이름, 고객사, 계약, 금액, 내부 프로젝트처럼 공개 전 확인이 필요한 정보
- `.env`, secret, service role key, access token 등 키워드가 들어간 문장
- 특정 개인이나 회사가 식별될 수 있는 실패 사례

초안에는 구체 정보 대신 `어떤 내부 프로젝트`, `A 고객사`, `비공개 설정값`처럼 바꿔 넣는다.

## 파이프라인

```text
허용된 MD 파일 읽기
→ Claude/Codex/바이브코딩 관련 문단 후보 찾기
→ 민감정보 의심 문장 표시
→ 초심자 막힘 포인트 추출
→ 쉬운 비유와 단계별 설명으로 draft 생성
→ 어떤 자료를 참고했는지 report 생성
```

## 1차 MVP 범위

- 로컬 스크립트로 실행
- 지정한 폴더의 `.md`, `.mdx` 파일만 읽기
- 점수가 높은 자료 일부만 사용
- `content-workbench/drafts`에 초안 생성
- `content-workbench/reports`에 검수 보고서 생성
- 자동 공개 금지
- Supabase DB 변경 금지
- Vercel 배포 금지

## 글 품질 기준

좋은 초안은 아래 조건을 만족해야 한다.

- 초심자가 무서워하는 지점을 먼저 인정한다.
- 기술 용어는 쉬운 비유와 함께 설명한다.
- “왜 이걸 하는지”를 명령어보다 먼저 설명한다.
- 대표님의 실제 시행착오가 익명화되어 들어간다.
- 따라 하기 단계가 작게 나뉘어 있다.
- 에러나 막힘을 실패가 아니라 정상적인 과정으로 설명한다.
- 자동 공개하지 않고 사람이 검수할 수 있게 만든다.

## 하지 말아야 할 것

- Obsidian 전체를 무단으로 훑기
- 민감정보를 그대로 초안에 넣기
- 유튜브나 외부 자료를 베껴서 글 만들기
- 검수 전 글을 `data/blog` 또는 Supabase `approved`로 보내기
- API 키, secret, 내부 계정 정보를 기록하기
- 글 개수를 늘리기 위해 얇은 AI 글을 대량 생산하기

## 성공 기준

1차 성공 기준:

- 지정 폴더에서 관련 MD를 찾아 초안 1개를 만든다.
- 초안과 별도 보고서가 생성된다.
- 보고서에 참고 파일과 민감정보 의심 항목이 표시된다.
- 빌드와 기존 블로그 동작을 깨지 않는다.

2차 성공 기준:

- 대표님이 초안 5개 중 2개 이상을 “사람이 다듬으면 공개 가능”하다고 판단한다.
- 초안에서 초심자 관점의 막힘, 쉬운 비유, 실제 경험이 분명하게 드러난다.
